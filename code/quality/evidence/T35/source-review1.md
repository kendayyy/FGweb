# T35 source review — Codex

Current source implements authenticated Push configuration, per-device registration/unregister and current external-notification lookup. Session/ban checks and CSRF/no-store remain enforced. Strict shared DTOs bound HTTPS provider endpoints and canonical browser keys; actual ECDH validation, canonical URL identity, keypair/endpoint advisory locks and stable owned-row locking reject foreign reuse without returning device secrets. External lookup requires an owned accepted target and current channel/source authority.

Shared notification authority adds only a fixed channel whitelist. The original private source predicate and default IN_APP SQL must match the recorded baseline byte-for-byte in canonical compiled output. Channel opt-outs are independent. EMAIL is restricted to invitations/reminders and current verified recipients; private messages use generic Push text. Source metadata, bans, blocks, membership, state and epochs are rechecked before each dispatch.

The delivery worker commits an outbox claim and per-target reservation before external I/O. Durable accepted targets are skipped on retry; definitive rejection is bounded to three attempts, while ambiguous delivery becomes terminal UNCERTAIN without automatic replay. Recovery requires stale outbox and target reservations and excludes a fresh in-flight target. Reservation refreshes the claim heartbeat. HTTP410/404 cleanup matches the current owned endpoint/key tuple, protecting rotated subscriptions. SMTP/VAPID cannot guarantee exactly-once delivery after an ambiguous network/provider outcome; this implementation avoids knowingly repeating accepted or uncertain dispatch.

Migration0024 adds only target receipt storage with outbox FK/cascade, unique outbox+target digest, bounded attempts/status/hash and recovery index. No raw email, Push endpoint/key or provider response is persisted there. Ownership derives through the existing outbox/notification/user relationship. Existing schema definitions and outbox constraints remain unchanged.

The reminder scanner uses real PostgreSQL UTC timestamps with microsecond-preserving canonical metadata and dedup keys, current scheduled state and membership, and locked batches. The due window begins ten minutes before scheduled time and ends at start. Completed, canceled, rescheduled, removed-member and opted-out sources are excluded. Eligibility and missing-dedup filtering precede the100-row limit, preventing already processed/opted-out early batches from starving later sessions. No1,000-call/live capacity claim follows from these fixtures.

The guarded runtime factory composes the unchanged in-app worker, external delivery worker and timer scanner. Importing the factory does not start main services. Startup failure closes owned resources; shutdown is idempotent and closes queues, pools and timer. Compiled runtime smoke uses real isolated PostgreSQL/Redis/BullMQ/API and explicitly mocked external adapters, separate from real provider acceptance.

Verification evidence retains failed RED rounds, interrupted lint, service-unavailable/startup attempts and all fixes. Final source lint, fresh serial TypeScript builds, real populated migration, compiled runtime and canonical source authority checks govern this review together with complete test receipts. Eight owned regression copies reverse exactly to frozen source; only relative imports and owned evidence/runtime/schema/queue namespaces change, preserving assertions. The native headed Chrome harness is a receiver test, not the T36 product PWA permission/install flow. Actual provider/native/inbox/Telegram receipts remain separate acceptance requirements. This source review alone does not close T35 or authorize production migration/deployment.
