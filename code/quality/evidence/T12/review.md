# T12 review

Implemented actual Nest REST/Socket.IO and PostgreSQL transactions with Redis pub/sub carrying only message identities. Each node resolves committed DTOs and current session/ban/membership per recipient. ROOM visibility does not grant access. No cached socket principal or blind room broadcast. Cookie failures never fall back to guest. Origin checks use the exact configured origin on connection and events/delivery. Public sender summaries omit provider identity/email.

History uses an exclusive descending createdAt/id cursor, at most50 rows and shared schemas. PostgreSQL timestamp formatting preserves six-digit precision and UTC independently of Node's timezone; the initial Date-based cursor skipped older rows and was fixed without changing expected counts. An actual disconnected/reconnected Socket.IO client recovers122 stored messages across pages with no duplicate IDs. Follow-up microsecond boundaries are tested explicitly.

Message creation checks current ACL in its DB transaction, uses the existing sender/conversation/client-message uniqueness for concurrent retries, and inserts one durable outbox job only for a new message. Dispatcher claims bounded25-job batches with SKIP LOCKED; publish failures increment attempts while keeping the job pending. A crash after Redis publish before marking delivered can replay an ID, so T13 must reconcile by messageId and REST history. No delivery/load/media target is claimed here. Rich attachments/reply/mentions are rejected explicitly until their owning T14 implementation.

Native tests verify guest read/send, all seven games, strict cursor validation, concurrent duplicate sends, origins, invalid cookies, private joins, current room membership despite PUBLIC visibility, revoked membership/session/ban before both subscription and delivery, and an actual PostgreSQL trigger failure rolls back message/outbox without emitting. Onboarding uses the unchanged T08 session/profile guard. Initial fixture failures (profile columns, expired session deletion) and runner failures (ESM Jest import, cwd/env for old tests) are preserved and do not count as behavior RED or PASS. Genuine behavior RED is codex-red-valid-fixture and codex-red-onboarding. All old tests remain unmodified.
