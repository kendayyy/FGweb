Refactor Loop 4 for **T16-FE (Frontend Online Users & Custom Status Panel)** is complete. All identified race conditions, event versioning issues, and profile hydration ordering bugs have been resolved.

### Architectural Corrections Implemented

1. **Monotonic Event Versioning (`eventVersionRef`)**:
   - Replaced wallclock `Date.now()` timestamps with a monotonically increasing counter (`eventVersionRef.current`).
   - Captured `requestEventVersion` when starting REST requests; snapshot items are only filtered if an offline event occurred *after* the request was initiated (`version > requestEventVersion`).
   - Resolves reconnect race conditions where offline events and reconnect requests share the same millisecond timestamp (**Reviewer Test 19**).

2. **Out-of-Order Profile Hydration & Status Badge Preservation**:
   - Tracked per-user latest status in `userStatesRef`.
   - Delayed profile HTTP lookups resolve against `latestKnownStatus` rather than stale payload status.
   - Prevents out-of-order profile HTTP lookups from overwriting newer status badges (**Reviewer Test 20**).

3. **Scope Generation & Connection Epoch Guards**:
   - Guarded all async handlers (`loadInitialOnline`, `loadMore`, `saveStatus`) with `generationRef.current === generation` and `!fetchCtrl.signal.aborted`.
   - Incremented `connectionEpochRef` on disconnect/reconnect to invalidate stale ACKs.
   - Enforced concurrency locks (`isLoadingMoreRef`, `isSavingStatusRef`).

4. **Enhanced Native Integration Smoke Test**:
   - Asserted mandatory profile link click and URL navigation (`/users/:id/profile`).
   - Asserted game switching and canonical presence scope updates.
   - Automatically switches to the "Tìm đội" tab on mobile viewports (< 1024) before capturing screenshots and verifying >=44px touch targets.
   - Cleaned up isolated Redis keys (`t16_fe_*`).
