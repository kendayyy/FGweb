# Codex CHATCRYPTO-BE local acceptance review

This review covers backend capabilities against spec17 and the approved BE/T37 acceptance rebaseline. It is not a PASS, production activation or completed frontend/QA declaration. Existing dated reviews remain historical; their pending statements are superseded only where later native evidence is verified.

Private routing retains ciphertext, signed public device keys and encrypted client recovery exports. The native devices/realtime/legacy suites exercise real Matrix SDK machines, authenticated HTTP, PostgreSQL and Socket.IO. Recovery is client-owned; a fresh client without keys cannot recover private plaintext from the encrypted server backup. Backend routing does not claim that arbitrary ciphertext sent by an untrusted client was positively decrypted; positive SDK interoperability is a separate native test.

Lobby stays public and uses separate server-held AEAD custody. Native OpenBao evidence checks TLS trust, randomized authenticated ciphertext, wrong binding/tamper rejection, role separation, nonexportability, rotation/rewrap, restart, seal/outage and credential revocation. The authenticated database/object archive excludes CA/token/Raft/client private keys and tests restoration with client-held recovery keys. See custody-config-review.md, custody-deadline-review.md and backup-restore-review.md, together with their recorded commands and later regressions.

Reports disclose only the user-selected submission and normalized images through distinct writer/admin-reader custody, owner ACL and read audit. This is user-provided evidence, not a cryptographic attestation of an arbitrary original message. Generic private notifications omit private text/image previews, and the owned Web Push receiver verifies actual TLS/ECE/VAPID and delivery authority. See report-image-review.md, report-read-review.md and private-notification-review.md.

Membership, device, history/cohort and current session/BAN checks remain enforced at producer/read boundaries. Room/admission native waits verify rollback after committed authority changes. The new quota suite also verifies latest sender/recipient BAN and real session expiry after transport advisory lock waits. SQL fixture bans exercise consumer denial; they do not implement the atomic administrative producer assigned to T37. The user-approved spec-gate-adoption.json preserves that separation and the 75 historical PASS records.

Transport quota is now explicit, atomic across API instances and shared between retained verification/to-device queues. ACK/expiry do not pretend to reclaim retained records; deletion reclaims the charge. Production ceilings are unselected. Persisted message history retains its existing product lifecycle rather than inheriting transport expiry or being deleted to satisfy a budget. Recovery remains one versioned encrypted record per user with the existing envelope size limit. Attachment size/draft retention and bounded cleanup retain their existing contracts; this change makes no physical total-storage or periodic cleanup throughput claim. Future production anti-abuse/capacity configuration must account for those distinct lifecycles.

The current 15-case quota suite and API build passed. Three native TLS fault-response tests prove clearing of the decoded rejected Transit buffer; they do not prove whole-heap zeroization.
