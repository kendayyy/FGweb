# CHATCRYPTO-BE verified legacy source read subset

Current-owner exact prerequisite: one new shared contract test, existing shared sources/dist and API paths remain owned. The manifest binds original message/conversation/sender/client IDs, type/text/reply/mentions, UTC microsecond source times and sorted original image metadata/physical digests. The item cannot disagree with its manifest. Contracts RED7 → GREEN7 and build pass; full contract regression is running.

Native isolated PostgreSQL/auth/Matrix-WASM device/files tests pass 6/6 (`legacy-read-boundary-green-1`). Access requires current membership/session/ban eligibility, KNOWN history in a private unreconciled state, a verified historical cohort with an actual user member row, an active owned device registered no later than verification, and an explicitly mapped PREPARED source receipt. Current membership alone, UNKNOWN history, missing cohort, foreign/new device and unmapped messages cannot grant old source access.

Source digest is recomputed from canonical source and actual image bytes and compared with the approved receipt. Changed original text/image bytes fail with conflict. Images use bounded handles, runtime/root/path/link checks, before/opened/after file identity checks, fixed WebP representation and metadata size parity. Reads do not normalize or change source bytes. Source rows, receipts, metadata and cohort rows are held under transaction locks; authorization/device checks run after I/O and before commit. A late actual BAN denies the response and clears all rejected image buffers. Batch and image responses are no-store/nosniff. Ordinary private history/image endpoints stay denied.

Cursor pagination preserves original microsecond ordering and only accepts a mapped cursor in the same cohort/conversation. It does not backfill historical membership. Missing source storage does not cause initialization to create a directory; source storage is checked lazily and fails closed. Sources, IDs/times and receipt states remain unchanged, including the original plaintext in this explicitly isolated legacy fixture.

These are source-read proofs only. They do not implement encrypted candidate upload, recipient roundtrip, reconciliation/cutoff, encrypted source recovery/rollback, historical main-database authorization, or a global E2EE claim. No main migration or source deletion happened. The previous GREEN1 attempt had 3 passing tests and one incorrect fixture URL; the nonexistent /images URL was replaced with both actual protected attachment routes, retaining 403 assertions and the failed record. The startup RED observed an unwanted directory creation; the lazy read-only fix passed the six-test suite.
