# T15 review

Shared rich composer and message/image components connect to the existing canonical Lobby/reconciler via minimal frontend consumer wiring. Existing source contracts, backend, database, auth, approved design and old tests remain unchanged. Colors/Inter tokens/layout are preserved; secondary composer buttons were adjusted after inspecting actual screenshots to avoid inheriting the primary button background.

XHR upload reports actual byte progress, keeps failed files for explicit retry, validates local MIME/size, and sends multipart context with session. Send failures retain content and uploaded draft IDs; unchanged retry payload reuses clientMessageId. Composer resources abort on unmount/signout and game/actor changes preserve the original Lobby lifecycle. Replies can be canceled; emoji inserts at selection and restores caret. Mention candidates are validated senders/mentions in current conversation history, deduplicated by opaque ID. This is not an invented directory; online/member directory expands in its owning later task. The server remains authoritative for mention eligibility.

User text is rendered through React text nodes. Image clicks resolve the protected metadata endpoint, validate its same-origin content URL, fetch binary content with credentials/no-store, show a disposable blob in a keyboard-accessible modal, revoke blob URLs, and restore previous focus on close. Forbidden responses show real errors and never fall back to remote attachment URLs. Guest/invalid/incomplete/signout users cannot send or upload. WebP image actions use the shared metadata and protected content route; there is no public static image mount.

Evidence includes genuine initial behavior REDs and a later RED for Escape while focus is inside emoji options; the latter was fixed in the composer container, preserving test assertions. The first image test fixture lacked an explicit HTTP content-type because jsdom Blob differs from native Response; the transport fixture was corrected to actual image/webp headers, without weakening production MIME checks.

Native compiled API + built web + real PostgreSQL/Redis checks upload PNG, choose reply and opaque mention, insert emoji, go offline, preserve image/text, retry with same ID, assert one persisted message/attachment/reply/mention and consumed draft, view actual protected WebP, close via Escape/focus, reconnect without duplicate, and verify literal script is inert. Inherited native checks also confirm old history scroll anchor, new-message action, game isolation, guest subscription, mobile drawer/tab behavior, all visible 44px targets and no overflow at 1440/1280/390/360. Screenshots include chat, image modal and mobile teams; actual layout was visually inspected.

One repeated modal screenshot run timed out after reconnect had succeeded. The native script now waits for the previous modal to be fully absent after Escape before the next viewport interaction; the original visibility assertion remains. The diagnostic run passed all viewports/modal/reconnect checks and closed owned resources; earlier failed output is retained.

All test schemas/storage and servers close after verification; public database is not migrated. Physical iPhone/Android, PWA/push and 1,000-call/live capacity are later tasks and not claimed. Vite's existing bundle size warning remains visible for later optimization.
