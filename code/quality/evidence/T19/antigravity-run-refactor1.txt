#### 2. Key Architecture & Feature Adjustments
1. **RoomsPage Hook Order & Fail-Closed Revocation**:
   - **Hook Order Safety**: Refactored `RoomsPage` into a guarded outer component (handling `auth.isLoading`, `auth.isError`, `!auth.user`, and incomplete onboarding) and a keyed inner component `RoomsPageInner` (keyed by `${user.id}_${routeRoomId || ''}`).    - **Fail-Closed 403 Alert**: If an outsider requests a private room (`/rooms/room-private`) that returns a 403 error, `RoomsPageInner` renders an explicit `<div role="alert">` displaying the permission denied message, rather than falling back to generic "Chọn hoặc tạo một phòng".

2. **Permissions & Role-Based UI Controls**:
   - Header settings button (`data-testid="room-header-settings-btn"`) and owner management controls are strictly guarded by `isOwner = activeRoom?.ownerId === actorUserId`. Non-owner members cannot view or trigger owner actions.
   - Member removal (`DELETE /api/v1/rooms/:id/members/:userId`) is guarded by `hasManageMembersPermission = isOwner || (isHelper && helperPermissions.includes('MANAGE_MEMBERS'))`.
   - Player capacity labeled as team slot size (1–10), separate from permanent member cap (up to 50).
3. **useRoomChat Real-Time & Reconnect Handling**:
   - Extra messages and subscriptions are keyed by `actorUserId` AND canonical `conversationId`.
   - Socket ack and incoming `message.created` events validate matching `conversationId` (never using `room.id`).
   - History and send operations consume `AbortSignal` and generation guards to ignore stale completions.
4. **Mobile Responsiveness & CSS Tokens**:
