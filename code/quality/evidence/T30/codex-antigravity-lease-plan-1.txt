PostgreSQL plans the query once per backend connection, reusing the cached execution plan via parameter binding and eliminating the 15–27ms per-query planning latency observed in `codex-t30-query-plan-diagnostic-2.txt`.

Only numeric `generic_plans`, `custom_plans`, and `cacheCount` metrics are logged from `pg_prepared_statements`.
