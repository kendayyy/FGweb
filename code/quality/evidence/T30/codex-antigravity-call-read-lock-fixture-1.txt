### 1. Diagnosis & Minimal Patch Details

1. **Defect**:
   - In the initial GREEN run (21/22 passed), `participants` failed on `CallParticipantSchema.parse()` because legacy test helper `seedCallAdmission` generates raw UUIDs, whereas the contract regex requires canonical IDs formatted as `admission_<uuid>`.
2. **Implementation**:
   - Added `canonicalDtoAdmission` near existing helpers without altering them:
     ```ts
     async function canonicalDtoAdmission<T extends { admissionId: string }>(seed: T) {
       const admissionId = `admission_${randomUUID()}`;
       const changed = await pool.query('UPDATE call_admissions SET id=$1 WHERE id=$2', [admissionId, seed.admissionId]);
       expect(changed.rowCount).toBe(1);
       return { ...seed, admissionId };
     }
     ```
   - Wrapped only `user1` and `user2` in the new `CallsService` concurrency callback:
     ```ts
     const user1 = await canonicalDtoAdmission(await seedCallAdmission(pool, `calls-shared-${method}-user-1`, game.id));
     const user2 = await canonicalDtoAdmission(await seedSecondMemberInCall(pool, user1, `calls-shared-${method}-user-2`, game.id));
     ```
   - Both PostgreSQL rows are updated to canonical format in the database before client tokens are generated and sockets connect.
3. **Preservation Guarantees**:
   - No changes to application code, contracts, validation schemas, or assertions.
   - All 15 original callbacks and legacy helpers (`seedCallAdmission`, `seedSecondMemberInCall`) remain completely untouched.
   - Real PostgreSQL authority remains intact (actual DB row updated, no mock objects).
