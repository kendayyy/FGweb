### 1. Evidence Context & Mechanism Summary

1. **Native60 Telemetry (`native60-boundary-inspection2.json`)**:
   - 5 gateway room-lock statement timeouts (`57014`) on backend PIDs 6228, 6229, 6230, 6231.
   - 15 matching PostgreSQL wait samples showed gateway queries waiting on row locks for `rooms`, blocked by API backend PIDs (6254, 6295, etc.) executing `CallLifecycleService.reconcileGroup` with holds lasting ~1.0s to ~2.2s.
2. **Native61 Execution (`native61-photo-timing-review1.json`)**:
   - Exit code 1: Two actors joined; third actor (Hà) remained in initial room-loading; original 5s Nhóm gọi region visibility failed.
   - Removing observer instrumentation did **not** remedy the underlying lock contention.
3. **Contention Mechanism in Compiled Source (`CallLifecycleService`)**:
   - `reconcileGroup` executes `SELECT id FROM rooms WHERE id=$1 FOR UPDATE` within a transaction.
   - While holding the exclusive lock, it performs remote LiveKit SFU RPCs (`listRooms`, `listParticipants`) and runs queries on `call_members` and `call_admissions`.
   - Webhook arrivals and the 1000ms periodic sweep invoke `reconcileGroup` unconditionally without in-flight checks or coalescing.
   - Multiple concurrent triggers queue behind `rooms FOR UPDATE`, executing serially and multiplying exclusive lock hold time ($N \times T$), exhausting connection pools and causing `57014` statement timeouts.

### 2. Candidate Internal Design: Per-Group Coalescing

- **Concept**: Coalescing of ordinary reconciliation triggers scoped strictly per call group ID (`Map<string, GroupCoalescer>`).
- **Mechanism**:
  - While an in-flight pass runs for group $G$, subsequent triggers set a `needsTrailingPass` flag and accumulate screen-share `ended` events.
  - When the in-flight pass completes, if `needsTrailingPass` is set, exactly **one trailing pass** executes.
- **Bounded Work**: For $N$ concurrent triggers on group $G$, work is bounded to at most **2 passes** ($O(1)$) instead of $N$ serialized passes ($O(N)$).
- **Fresh Read Guarantee**: The trailing pass executes after all burst triggers have arrived, performing fresh LiveKit SFU and PostgreSQL reads to ensure eventual consistency.
- **Screen Share Safety**: Screen-ended `{identity, at}` event payloads are accumulated so no track unpublish event is dropped.
- **Strict Invariants**:
  - `rooms FOR UPDATE` and `call_groups FOR UPDATE` lock modes remain strictly exclusive (no `SHARE` relaxation).
  - Transaction boundaries and remote RPC placement remain strictly preserved.
  - Actor and `liveLease` validations remain intact.
  - Deadlines (45000ms deadline, 5s assertion) and 1000ms sweep interval remain immutable.
  - No event processing is skipped.
