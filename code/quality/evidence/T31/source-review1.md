# T31 source review — Codex

Reviewed the current source, additive database migration, contract validators, production module registration and generated build proposals. Final test/build/cleanup acceptance is recorded separately; this review alone does not mark the task PASS.

- The parser contains no HTTP/DNS/filesystem fetch. It permits exact HTTPS YouTube/Twitch hosts, excludes userinfo/nonstandard ports and validates video/channel identity before generating a canonical URL. Tracking parameters are discarded. Raw whitespace/control/backslash validation now occurs before the installed Zod URL validator can trim input. The retained API39/40 failure, URL probe and new contract RED demonstrate that correction.
- Every external-source operation uses the existing call transaction/control locks and checks the current session-bound admission before and after its database operation. Existing actor, room membership, ban, onboarding, call state, lease and grace authority remains in CallsService. Source configuration does not confer publishing/moderation rights. GET/PUT/POST/DELETE all have production session/onboarding/CSRF guards and the existing exception filter.
- SQL values are parameters. A unique call-group constraint plus locked atomic upsert preserves one complete source per call, with stable row ID/createdAt on replacement. Client-provided authority/structured IDs/health state are rejected by the strict request schema. The DTO explicitly reports unknown availability; syntactic validity never establishes existence or embeddability.
- Migration0023 adds nullable identity fields and a consistency check without deleting legacy sources. Conservative recognized-URL backfill preserves unrecognized legacy rows. Invoker triggers remove only the configuring member's source on actual leave, or the source for the closed call; they do not remove persistent rooms, conversations or team membership. Existing active-member FK and transaction rollback remain enforced. Main-schema migration is not performed by this task.
- Call listing uses EXISTS to advertise only the source-present boolean. Source URLs remain behind current-call admission. The new module is registered in the actual production AppModule. POST remains compatible alongside the required PUT/GET/DELETE contract.
- Tests use real owned PostgreSQL schemas and synthetic actors with actual production guards and native SFU room-control APIs. Original admission/publishing tests and their assertion/deadline bytes remain frozen. T31 has no frontend/embed/player or browser-media/production/1,000-call acceptance claim; those retain their designated gates.

No unresolved source finding identified in this review. Final acceptance requires current successful command records, cleanup proof, full original-file/gate/baseline audit, history, and public staged privacy review before GitHub backup.
