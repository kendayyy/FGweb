2. **Composite Replies FK Parent Deletion (`messages_reply_to_same_conversation_fk`)**:
   - Updated the composite foreign key clause in [`packages/database/migrations/0001_left_the_call.sql`](file:///E:/FGweb/code/packages/database/migrations/0001_left_the_call.sql):
     ```sql
     ALTER TABLE "messages" ADD CONSTRAINT "messages_reply_to_same_conversation_fk"
     FOREIGN KEY ("reply_to_id", "conversation_id")
     REFERENCES "messages"("id", "conversation_id")
     ON DELETE SET NULL ("reply_to_id")
     ON UPDATE NO ACTION;
     ```
   - Specifying column-specific `ON DELETE SET NULL ("reply_to_id")` ensures that deleting a replied-to parent message sets `reply_to_id` to NULL while leaving `conversation_id` intact, preventing PG `23502` (`not_null_violation`) and retaining the reply message in its original conversation.
   - Documented the Drizzle DSL mapping limitation in [`packages/database/src/schema/messages.ts`](file:///E:/FGweb/code/packages/database/src/schema/messages.ts).

## 3. Metadata & Limitations

- **Custom Migration SQL Limitation**: Drizzle Kit DSL represents composite FK `onDelete('set null')` without column-level target parameters in schema definitions. The forward migration SQL (`0001_left_the_call.sql`) explicitly uses PostgreSQL 17 `ON DELETE SET NULL ("reply_to_id")` syntax. Future migration generators should take care not to overwrite this custom clause when generating schema diffs.
- **FK Schema Qualification**: All foreign key references in `0001_left_the_call.sql` remain normalized without explicit `"public".` schema qualification to maintain search_path isolation across test environments.
