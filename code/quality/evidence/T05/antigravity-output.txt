## 2. Relational Constraints & Schema Details

1. **DM Pair Canonical Normalization & Uniqueness**:
   - `user1_id < user2_id` CHECK constraint (`dm_canonical_order`) prevents unnormalized pair order and self-pairs (PG `23514`).
   - `UNIQUE(user1_id, user2_id)` constraint (`dm_pair_unique`) prevents duplicate DM creation (PG `23505`).
   - One conversation per Lobby linked to T04 `lobbies.id` via `UNIQUE(lobby_id)`.
2. **Messages, Resend Dedup, and Relational Same-Conversation Reply**:
   - `client_message_id` deduplication via `UNIQUE(sender_id, conversation_id, client_message_id)` (PG `23505`).
   - Cursor index on `(conversation_id, created_at, id)` for stable pagination.
   - Same-conversation reply enforced at the database level using composite foreign key:
     `FOREIGN KEY (reply_to_id, conversation_id) REFERENCES messages(id, conversation_id)`
     Any cross-conversation reply attempt is rejected relationally with PostgreSQL error `23503`.
3. **Attachments & Mentions**:
   - Attachments enforce conversation matching via composite FK `(message_id, conversation_id) REFERENCES messages(id, conversation_id)`.
   - Mentions enforce uniqueness via `UNIQUE(message_id, mentioned_user_id)`.
4. **Social Relations**:
   - `friendships`: Enforces normalized order `user1_id < user2_id` (rejects self & reverse friendships with PG `23514`) and `UNIQUE(user1_id, user2_id)` (PG `23505`).
   - `friend_requests`: Enforces `sender_id <> receiver_id` (PG `23514`) and `UNIQUE(sender_id, receiver_id)` (PG `23505`).
   - `blocks`: Enforces `blocker_id <> blocked_id` (PG `23514`) and directed `UNIQUE(blocker_id, blocked_id)` (PG `23505`).
