### 1. Key Fixes Implemented

#### A. Actor Transition State Reset (`useDirectMessages.ts`)
- **Issue (`actor-review.test.tsx`)**: When `actorId` transitioned directly from `actorA` to `actorB` without passing through `null`, `useEffect` only cleared state `if (!actorId)`. As a result, `activeConversationId` (`review-conversation-a`), `messages`, `unreadCounts`, and pending errors leaked to the newly logged-in `actorB`.
- **Fix**: Updated `useEffect` on `[actorId]` in [useDirectMessages.ts](file:///E:/FGweb/code/apps/web/src/features/direct-messages/useDirectMessages.ts#L66-L81) to reset all hook state (`activeConvIdRef`, `activeConversationIdState`, `messages`, `unreadCounts`, `sendError`, `isSending`, `isLoadingMessages`, `nextCursor`, `hasMore`, `seenMessageIdsRef`, `subscribedConvsRef`) on ANY `actorId` change.

#### B. Synchronous Conversation Selection Reference
- Synchronized `activeConvIdRef.current = id;` directly inside `setActiveConversationId` callback so async handlers and event listeners immediately observe the newly selected conversation before deferred `useEffect` renders.

#### C. Async Epoch & Stale Response Guards in `startOrOpenDM`
- Added epoch check `if (epochRef.current !== currentEpoch)` after `conversationsQuery.refetch()` in `startOrOpenDM` so delayed refetch completions do not select stale conversations across actor transitions.
