# Recovery client review before UI/read-path work

This review applies the already locked ADR001 Recovery and Lobby custody paragraphs: native encrypted Megolm export, independently generated256bit user-held code, ciphertext-only CAS backup, import historical room keys without cloning identity or granting current trust. Installed primary SDK18.6.0 declarations confirm importRoomKeys only imports room keys and returns public imported session identifiers; InboundGroupSession.hasBeenImported identifies import provenance, and exportRoomKeys accepts a native session predicate. DecryptedRoomEvent sender/device labels are untrusted without verified native device state. Do not use forwardingCurve25519KeyChain as authentication; SDK explicitly documents it as unreliable.

Current live decrypt correctly rejects unverified senders but consequently cannot expose recovered history after loss of the old trusted device. Separate explicit recovered-history display may operate only after the user successfully imports their own encrypted backup using the independent code, with exact recovered room/sender-key/session identifiers returned by native import, native imported-session evidence, normal current server history ACL/membership interval eligibility, native Megolm decryption and all existing outer/inner FG bindings. It must label recovered content as historical and sender/device currently unverified; it cannot set SAS/cross-signing/native trust, accept an arbitrary import without the code, enable autonomous old-key requests/forwarding, send to an unverified recipient, or override live malformed/tampered bindings. Current-verified live messages continue through the existing strict path. Failure/missing backup/wrong code/password reset must not grant recovered provenance or render an empty successful restore.

Public imported identifier custody is per native machine session and only comes from successful native backup decryption/import; no server/client flag can grant current trust. New device retains its new identity. Old key possession never bypasses current history ACL: new member and rejoin-exclusion histories remain rejected by normal backend pathways. Native tests must prove correct/wrong/missing keys, actual historical read, new identity/unverified trust, invalid binding/tamper rejection and no future key sharing. Headed restore must exercise actual server CAS and native import; do not claim completion from key count alone. No ADR/algorithm/version/spec/checker/old PASS changes. This is a scoped review prerequisite, not a completed acceptance or independent QA review.
